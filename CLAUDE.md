# Kiln

Open-source library of ~200 animated React components (React 19, Tailwind v4, Motion, lucide-react), light and dark, plus a gallery app to see each one. Two ways to use it: copy components in (shadcn registry at `/r/<id>.json`, or `node scripts/kiln-add.mjs`), or install the npm package `@electro1207/kiln` (built from `src/kiln/` into `packages/kiln/`). Both are generated from the sources by scripts; never edit generated output.

## Two jobs, two guides

- **Building an app with Kiln** (this repo's gallery or any other project): read `src/kiln/CLAUDE.md`. It is the consumer guide, copied with the `kiln/` folder, so it is self-contained: setup, component catalogue, usage rules, motion rules, do/don't pairs.
- **Changing the library itself**: read the same guide, then `docs/CONVENTIONS.md`. **`docs/CONVENTIONS.md` is binding.** Each rule in it comes from a fault that shipped. Also: `docs/API.md` (props, controlled/uncontrolled, sizes, slots), `docs/TAXONOMY.md` (section, group, folder of every entry; generated from `registry.ts`), `CREDITS.md` (media licences).

If a rule in `src/kiln/CLAUDE.md` and `docs/CONVENTIONS.md` ever differ, CONVENTIONS wins; fix the guide. When you add, move or rename a component, update the catalogue in `src/kiln/CLAUDE.md` too.

## Layout

| Path | What |
| --- | --- |
| `src/kiln/` | The library: `tokens.css` (the only place colours, radius, shadows change), `kiln.css` (tokens to Tailwind utilities), `motion.ts`, `theme.tsx`, `cn.ts`, `controllable.ts`, `components/<folder>/<Name>.tsx`, `components/shared/` |
| `src/gallery/` | The showcase app. Never imported by `src/kiln/`, never copied to other projects |
| `src/gallery/demos/*.tsx` | Demo files. Each exports `category: Category` with `entries` |
| `src/gallery/registry.ts` | `TAXONOMY` (sections, groups, entry order) and the glob that loads demos |
| `src/gallery/ui.tsx` | Demo-only helpers: `Stage`, `Variant` |
| `src/gallery/studio/` | Theme studio (`#/studio`) that writes a new `tokens.css` |
| `src/kiln/index.ts`, `src/kiln/groups/` | GENERATED by `scripts/gen-index.mjs` (`npm run gen:index`): the package entry points. Run it after adding, renaming or removing a component; it stops on an export-name clash (fix in its `RENAMES`) |
| `scripts/`, `packages/kiln/`, `vite.lib.config.ts` | `gen-registry.mjs` (shadcn registry into `public/r/`, run by `npm run build`), `build-lib.mjs` (`npm run build:lib`: npm package into `packages/kiln/`), `kiln-add.mjs` (zero-dependency installer). `packages/kiln/package.json` is the package manifest |
| `docs/`, `CREDITS.md`, `public/demo/` | Docs; media credits; demo media |

## Gallery: adding a demo

1. Write the component in `src/kiln/components/<folder>/<Name>.tsx` (see "New component" in `src/kiln/CLAUDE.md`).
2. Add an entry to the `entries` of the matching `category` in `src/gallery/demos/<file>.tsx`:
   `{ id: "kebab-id", name, summary: "One sentence: what it is for.", files: [...], Demo: MyDemo }`. `id` is unique across the gallery and becomes the anchor (`#/<group>/<id>`).
3. `files` lists project-root paths a person must copy, primary component first: `src/kiln/components/<folder>/<Name>.tsx`, then every local file it imports, transitively (`src/kiln/motion.ts`, `src/kiln/cn.ts`, `src/kiln/controllable.ts`, `components/shared/*`, other components). It feeds the Code tab, so it must be exact. Dependency recipe: section 3 of `src/kiln/CLAUDE.md`.
4. Place it in `TAXONOMY` in `src/gallery/registry.ts` (group `entries` array: ids in display order). An unlisted entry still appears at the end of its demo file's fallback group, but list it.
5. Demos use `Stage`/`Variant` from `src/gallery/ui.tsx`, show real variants and states, use cult-classic copy, and use only free media (credit in `CREDITS.md`, `src/gallery/App.tsx` footer `CREDITS` and the media's own caption).
6. A new group goes in `TAXONOMY` with a `summary`; a new section likewise. Keep `docs/TAXONOMY.md` in step.

## Commands

```bash
npm install
npm run dev      # vite, http://localhost:5190
npm run build    # tsc -b && vite build
npm run lint     # oxlint
```

No test suite. Verification is type-check, build and looking at it.

## Verification (before calling anything done)

1. `npx tsc -b` and `npm run build` pass with no errors; `npm run lint` clean on files you touched.
2. Run `npm run dev` and look at the change in a **real browser** (Playwright or similar), not just the build. Exercise every interaction: hover, press, keyboard (Tab, arrows, Enter, Esc), open/close, resize.
3. **Screenshots in both themes**, and at 390px wide for anything that changes layout. For animated interactions, capture frames and check for overlap, overshoot, wrong-row frames, text reflow, flicker when hovering across gaps, 1px icon misalignment (full procedure in `docs/CONVENTIONS.md` under Testing).
4. **fps**: scroll and sweep/drag the pointer over the demo at 1x and 4x CPU throttle; zero long frames at 1x, no runs of long frames at 4x.
5. Check the demo's Code tab lists exactly the files the component needs (copy into a clean Vite project if unsure).
6. Don't edit files outside your task; other agents may be working in the same tree.
